\section{Methodology}

Every file in this report has been classified as one of three statuses:

\begin{itemize}[leftmargin=1.2cm]
  \item \reqBadge{} — the live application, test suite, or development environment
    will fail or become non-functional if this file is removed. Examples: Django
    settings, URL routing, model definitions, React entry points.
  \item \optBadge{} — removing this file reduces capability (loses tests,
    seed data, a debug command, a migration script) but the running application
    continues to work. Example: data loaders, optional admin commands, test fixtures.
  \item \deadBadge{} — not referenced by any live import or runtime path. Safe
    to delete. Typically: development-time debug scripts, stale output logs,
    abandoned prototypes.
\end{itemize}

\subsection{Excluded directories}

Large auto-generated or irrelevant directories are not enumerated file-by-file.
They are listed below as single entries.

\fileEntry{.git/}{n/a}{Git version control metadata — object store, refs, hooks, and configuration for every commit in the repository history.}{Destroys the repository history; project becomes a plain directory with no version control.}

\fileEntry{frontend/node\_modules/}{\reqBadge\ for dev}{NPM-installed frontend dependencies (\texttt{react}, \texttt{react-dom}, \texttt{react-router}, \texttt{recharts}, \texttt{react-simple-maps}, \texttt{jspdf}, \texttt{tailwindcss}, etc.). Reinstallable from \texttt{package-lock.json}.}{Frontend dev server cannot start; \texttt{npm install} recreates it.}

\fileEntry{backend/node\_modules/}{\deadBadge}{Stray NPM dependencies installed at the backend root for a legacy Node utility (likely \texttt{generate\_comparison\_pdf.js}). The live backend is Python only; none of these packages are imported by Django.}{Nothing breaks. Safe to delete entirely, saves hundreds of MB.}

\fileEntry{backend/.venv/}{\reqBadge\ for dev}{Project-local Python virtual environment with installed pip dependencies (Django, DRF, sentence-transformers, setfit, keybert, gliner, rapidfuzz, etc.).}{Backend cannot run until dependencies are reinstalled with \texttt{pip install -r requirements.txt}.}

\fileEntry{backend/search/models/intent\_model/}{\reqBadge}{Trained SetFit intent classifier (\texttt{model.safetensors}, \texttt{model\_head.pkl}, \texttt{config\_setfit.json}, tokenizer files, \ldots\ 129 MB total). Loaded at startup by \texttt{nlu\_engine.ModernNLUEngine}.}{NLU falls back to the regex intent detector; functional but misses subtleties on ambiguous phrasing.}

\fileEntry{frontend/build/}{\optBadge}{Output of \texttt{npm run build} — minified production bundle (\texttt{static/js/*.js}, \texttt{static/css/*.css}, HTML shell). Regenerable anytime.}{Production static bundle is gone until \texttt{npm run build} is re-run; dev server (\texttt{npm start}) still works.}

\fileEntry{\_\_pycache\_\_/ (every Python package)}{n/a}{Python bytecode cache automatically regenerated on import. Every Django app, service, and script directory has one.}{Deleted and regenerated freely; no impact.}

\fileEntry{migrations/\_\_pycache\_\_/}{n/a}{Same as above but for migration files.}{Same; regenerated.}

\fileEntry{.pytest\_cache/}{n/a}{Pytest's last-run cache.}{Regenerated on the next test run.}

\fileEntry{.claude/}{n/a}{Claude Code session state for this repository. Editor tool, not project code.}{Claude Code loses session history for this repo; project is unaffected.}

\section{Backend — Search Engine (\texttt{backend/search/})}

The search app is the ML-powered core of the product: it exposes a single
DRF viewset (\texttt{/api/search/}) that takes a natural-language query
(e.g.\ \textit{``buy cheap sugar from china under \$500''}) and returns a
ranked list of supplier/buyer profiles aggregated from the
\texttt{trade\_data.Transaction} table. The pipeline is NLU $\rightarrow$
subcategory resolution $\rightarrow$ ORM aggregation $\rightarrow$ composite
ranking. The 8 source files below are the live files in this app after the
recent dead-code cleanup removed \texttt{nlp.py}, \texttt{vector\_store.py},
\texttt{candidate\_retrieval.py}, \texttt{ranking.py}, \texttt{ranking\_ltr.py},
\texttt{train\_ltr.py}, \texttt{ltr\_dataset\_builder.py},
\texttt{build\_search\_index.py}, \texttt{train\_intent.py}, and
\texttt{query\_parser.py}.

\fileEntry{backend/search/apps.py}{\reqBadge}{Django \texttt{AppConfig} registering the app under the name \texttt{search}. Referenced in \texttt{settings.INSTALLED\_APPS}.}{Django refuses to load the app; \texttt{/api/search/} routes disappear.}

The search app intentionally stores no state of its own; all state lives in \texttt{trade\_data.Transaction}.}{Django management commands (\texttt{makemigrations}, \texttt{check}) warn that the app is misconfigured.}

The entire search feature is down.}

\fileEntry{backend/search/services/aggregation.py}{\reqBadge}{\texttt{SupplierAggregator} --- pure Django-ORM aggregation over the \texttt{Transaction} table.

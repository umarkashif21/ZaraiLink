================================================================================
ZARAILINK MODEL COMPARISON: TRADE DATA vs. TRADE LENS
================================================================================

This document explains the technical and structural differences between the 
two primary data apps in the ZaraiLink backend.

--------------------------------------------------------------------------------
1. CORE PURPOSE
--------------------------------------------------------------------------------

TRADE DATA (The Ledger):
The "Single Source of Truth." This app handles the massive ingestion of all 
raw trade records (imports/exports). It is built for comprehensive search, 
auditability, and system-wide intelligence.

TRADE LENS (The Dashboard):
A specialized, high-performance "deep-dive" app. It is designed specifically 
for the TradeLens product dashboard to show deep analytics for a curated set 
of high-value sub-categories.

--------------------------------------------------------------------------------
2. DATABASE ARCHITECTURE
--------------------------------------------------------------------------------

TRADE DATA (Hierarchical & Normalized):
Uses a 4-level deep hierarchy to maintain strict data integrity:
   Product -> Category -> SubCategory -> Item
Transactions are linked at the lowest level (Item). This structure is ideal 
for broad searches (e.g., searching for all "Dairy" category products).

TRADE LENS (Flat & Denormalized):
Uses a simple 2-level structure:
   TradeLensProduct -> TradeLensTransaction
This structure prioritizes speed. By "flattening" the data, we avoid complex 
database joins, making the TradeLens dashboard feel instant for the end-user.

--------------------------------------------------------------------------------
3. TRANSACTION DATA FIELDS
--------------------------------------------------------------------------------

TRADE DATA (Raw & Generic):
- Geography: Uses 'origin_country' and 'destination_country'.
- Categorization: Strict FK links to the product hierarchy.
- Scale: Designed to hold millions of rows.

TRADE LENS (Enriched & Specific):
- Geography: Uses 'buyer_country' and 'seller_country' directly.
- Spatial Data: Includes specific 'port' and 'province' fields for mapping.
- Isolation: Models are marked "Isolated for easy deletion," allowing the 
  TradeLens data to be cleared or re-populated without touching the main 
  ledger's history.

--------------------------------------------------------------------------------
4. SUMMARY OF DIFFERENCES
--------------------------------------------------------------------------------

| Feature             | Trade Data (Ledger)        | Trade Lens (Dashboard)    |
|---------------------|----------------------------|---------------------------|
| Data Hierarchy      | 4-Tier Complex             | 2-Tier Flat               |
| Normalization       | Strictly Normalized        | Highly Denormalized       |
| Performance Goal    | Search Accuracy            | UI/Chart Speed            |
| Geography Detail    | Country Level Only         | Port & Province Detail    |
| Impact of Deletion  | System-Wide Data Loss      | Local Dashboard Update    |
